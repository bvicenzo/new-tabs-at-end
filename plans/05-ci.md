# Plano 05 — CI

## Contexto

Os planos 01 a 04 deixaram o projeto com lint, typecheck e testes, mas tudo é validado só localmente, e o template de PR pede que você rode `npm test` e `npm run lint` à mão. Este plano coloca essas mesmas verificações no GitHub Actions para todo PR e todo push no `master`. Também confere o título do PR, que vira o commit do squash e, no plano 07, a entrada do release-please.

O plano 06 (a extensão) será o primeiro a receber esse CI.

## Decisões tomadas

- **O CI avisa, mas não bloqueia.** O repositório é privado no plano Free, onde a proteção de branch e os rulesets respondem 403. O CI roda e marca o PR de vermelho, mas o merge continua liberado. Exigir os checks passa a ser tarefa do plano 07, quando o repositório ficar público para a Web Store. Fica registrado na ADR 0007.
- **Cobertura de 100% por arquivo, nas quatro métricas** (statements, branches, functions, lines), sobre o `COVERED_SOURCES` do `vitest.config.ts`: o plugin hoje e o `src/` a partir do plano 06. Hoje o projeto está em 100% em tudo (436/369/170/349).
- **Dependabot semanal e agrupado** para npm e GitHub Actions, com um PR por ecossistema. O `typescript` fica travado abaixo de 6.1 (ADR 0005). O prefixo de commit é `build(deps)` (npm) e `ci(deps)` (Actions), que o hook aceita.
- **O título do PR é validado pelo próprio `.githooks/commit-msg`.** Assim há uma só fonte para o padrão de Conventional Commits: o job grava o título num arquivo e roda o hook sobre ele.

## Arquivos

**`.github/workflows/ci.yml`**
- Gatilhos: `pull_request`, e `push` no `master`.
- `permissions: contents: read`.
- `concurrency` por workflow e ref, com `cancel-in-progress` quando for PR.
- **Job `checks`:**
  - `actions/checkout@v7`;
  - `actions/setup-node@v7` com `node-version-file: .node-version` e `cache: npm`;
  - `npm ci`, que executa o `prepare`; isso é inofensivo no runner;
  - `npm run lint`, `npm run typecheck` e `npm run test:coverage`. A cobertura substitui o `npm test`, porque roda a mesma suíte.
- **Job `pr-title`:**
  - só roda em `pull_request`, com os `types` `opened`, `edited`, `synchronize` e `reopened`, para que mudar o título rode o job de novo;
  - o título entra por `env: TITLE: ${{ github.event.pull_request.title }}`, nunca interpolado no `run`, para evitar injeção de shell;
  - `printf '%s\n' "$TITLE" > "$RUNNER_TEMP/title"` e depois `sh .githooks/commit-msg "$RUNNER_TEMP/title"`.

**`.github/dependabot.yml`** (versão 2)
- `npm` em `/`, semanal, com `groups` reunindo todas as dependências num PR. Tem `ignore` para `typescript` nas versões `>=6.1.0`, com um comentário apontando para a ADR 0005. `commit-message.prefix: build`, `include: scope`.
- `github-actions` em `/`, semanal, agrupado. `commit-message.prefix: ci`, `include: scope`.

**`vitest.config.ts`**
- `coverage.thresholds: { 100: true, perFile: true }`.
- Um comentário de uma linha lembrando que o limite vale também para o `src/`.

**`docs/decisions/0007-ci-checks-are-advisory-while-private.md`** (contexto, decisão, consequências)
- **Contexto:** a proteção de branch e os rulesets dão 403 num repositório privado do plano Free.
- **Decisão:** o CI roda em todo PR, mas não bloqueia o merge.
- **Consequências:** quem faz o merge confere os checks. No plano 07, ao tornar o repositório público, exigir os jobs `checks` e `pr-title` no `master` (squash only, sem push direto).

**`README.md`**, seção "Development"
- Uma linha sobre o CI: o que ele roda, e que a cobertura exigida é 100% por arquivo.

**`.github/pull_request_template.md`**
- A checklist passa a dizer `npm run lint`, `npm run typecheck` e `npm run test:coverage` (100%), e que o CI roda os mesmos comandos.

**`plans/05-ci.md`**
- Cópia deste plano, em pt-BR.

## Execução

1. Branch `ci/github-actions` a partir do `master` atualizado.
2. Criar e editar os arquivos acima.
3. Commits no formato Conventional Commits, sem atribuição de IA, por exemplo:
   - `ci: run lint, typecheck and coverage on every pull request`;
   - `build: require full coverage per file`;
   - `docs: record that CI checks are advisory while the repository is private`.
4. Push e abertura do PR com o título `ci: add the GitHub Actions workflow and Dependabot`. A descrição segue o template, em inglês e sem "Generated with Claude Code".

## Verificação

- **Local, antes do push:**
  - `npm run lint`, `npm run typecheck` e `npm run test:coverage` verdes;
  - o limite de cobertura funciona: um `src/probe.ts` temporário, com um `if` que nenhum teste cobre, faz o `npm run test:coverage` falhar apontando o arquivo. Depois o arquivo é apagado pelo nome;
  - o comando do job `pr-title`, rodado localmente sobre um título válido e um inválido, sai com 0 e com 1, respectivamente.
- **No PR:**
  - os jobs `checks` e `pr-title` ficam verdes (`gh pr checks`);
  - mudar o título para um inválido (`gh pr edit --title "add ci"`) deixa o `pr-title` vermelho, e voltar ao título válido o deixa verde de novo;
  - o GitHub aceita o `dependabot.yml`, ou seja, não aparece erro de configuração do Dependabot no PR nem na aba de insights.
- **Depois do merge:**
  - o push no `master` dispara o workflow, e ele fica verde;
  - o primeiro PR do Dependabot, na semana seguinte, tem um título que passa no `pr-title`.
